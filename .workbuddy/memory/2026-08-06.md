## 修复：全屏吞掉横屏方向识别

用户反馈：v13 在「开始游戏」时自动 requestFullscreen 后，浏览器不再触发 orientationchange，导致手机转横屏也无法进入游戏（卡在提示页）。

### 改动
- `web/js/games/uno.js`：
  - 移除 `startMatch()` 中的 `this.tryFullscreen()`，**不再自动全屏**。

  - 顶部栏新增「⛶」全屏按钮（`data-action="fullscreen"`），**用户手动点击**才调用 `tryFullscreen()`，此时已横屏不会卡。

- `web/sw.js`：`moyu-v13`→`moyu-v14`。

## 修复：既要自动全屏、又要能识别转横屏（v15）

用户要求：保留「进 UNO 自动全屏隐藏地址栏」，同时手机转横屏仍要能被识别进入游戏。v14 因移除自动全屏才解决了卡死，但用户不想放弃全屏。

### 根因
全屏（requestFullscreen）下，部分浏览器不再派发 `orientationchange` 事件，仅靠事件监听会在横屏检测上失灵。

### 改动
- `web/js/games/uno.js`：
  - `startMatch()` 重新加入 `this.tryFullscreen();`（用户点击「开始游戏」即用户手势内调用，通常被允许）。
  - `checkLandscape()` 增强为三重判定：matchMedia(`orientation:landscape`) → `screen.orientation.angle`（90/-90/270）→ 尺寸/旧 `window.orientation` 回退。
  - 新增 `pollOrientation()` + constructor 里 `setInterval(pollOrientation, 250)` 主动轮询兜底；`destroy()` 中 `clearInterval`。即使全屏下事件不触发，定时读取几何也能识别转横屏。
  - `updateOrientation()` / `pollOrientation()` 在转成横屏时清除“直接横屏开始”按钮与 1.2s 提示计时器。
  - `tryFullscreen()` 增加 `if (!el) return;` 空安全（防御性，也避免无 documentElement 环境抛错）。
- `web/sw.js`：`moyu-v14`→`moyu-v15`。

## 关键修复：不再开局自动全屏，改为“横屏后下次触摸再全屏”（v16）

用户反馈 v15（开局 `tryFullscreen`）在手机上仍卡在转屏提示。
根因：竖屏状态下请求 `requestFullscreen`，部分手机浏览器会把屏幕方向锁死在竖屏，物理转过去页面也不跟着转 → 永远卡转屏。v14（无自动全屏、窗口模式检测）本身是正常的。

### 改动
- `web/js/games/uno.js`：
  - `startMatch()` 移除 `this.tryFullscreen();`（不再竖屏开局自动全屏）。
  - 检测在**窗口模式**完成（竖屏显示转屏提示 → 用户转横屏 → 轮询/matchMedia/resize 识别 → 渲染圆桌），与 v14 一致可靠。
  - 新增 `armedFullscreen` 标志 + `pointerdown` 监听 `fsHandler`：检测到真横屏（`checkLandscape()` 为真，排除伪横屏）后，用户**下一次触摸**（手势）自动触发 `tryFullscreen()`，既保留全屏、又不会锁死方向。
  - `fsHandler` 守卫：`if (this.armedFullscreen && this.checkLandscape())`，避免“直接横屏开始”（伪横屏）时误全屏导致再次锁方向。
  - 桌面（开局即横屏）首次点击也会自动全屏。
  - `destroy()` 中 `removeEventListener('pointerdown', this.fsHandler)`。
- `web/sw.js`：`moyu-v15`→`moyu-v16`。

### 验证

- 线上 curl：HTTP 200、`moyu-v16`、无开局自动全屏、`armedFullscreen = true`、`addEventListener('pointerdown'` 均生效。

### 部署
- 成功部署到原 CloudStudio 沙箱链接。
